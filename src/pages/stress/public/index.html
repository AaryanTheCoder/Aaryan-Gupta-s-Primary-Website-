WHAT THE NUMBERS MEAN

Real measurements.
Transparent scoring.

This is a browser benchmark, influenced by Chromium, its JavaScript engine, graphics driver, power settings, and background apps. It does not certify hardware stability or replace a native diagnostic tool.

How do points work?

We use normalized throughput and geometric means, an approach used for workload groups in Geekbench 6. These are Stress Lab v2 points, with our own synthetic reference rates, not Geekbench, Cinebench, or 3DMark scores.

Each workload earns 1,000 × measured rate ÷ reference rate. CPU reference rates: integer 50 million iterations/s; floating point 10 million iterations/s; buffer 2,000 MB/s. Graphics references: ray marching 25 MPix/s; texture sampling 250 MPix/s. These are fixed scale anchors, not a measured reference PC.

Each CPU score is the geometric mean of its three workload scores. Graphics uses the geometric mean of its two scene scores. Overall is the geometric mean of CPU single, CPU multi, and graphics. Compare graphics and overall scores only within the same API, renderer type, resolution, precision, and timing profile. V2 results are separate from v1. Twice the throughput in every workload means twice the score. Overall requires a completed full suite.

What exactly runs?

CPU: deterministic integer hashing, dependent floating-point math, and a 1 MiB buffer read/write test per worker. Each block is checked against a known answer. Workers warm up for 150 ms before timing. Single worker is not a pinned physical core. Multi-worker tests use your selected count (up to 64); the default is capped at 16.

Graphics: a 64-step torus ray marcher and 32 dependent texture samples per pixel, with 500 ms warmups. Auto selects 320 × 180 for detected software renderers or WebGL1, and 1280 × 720 for other WebGL2 renderers. You can choose up to 1920 × 1080. Resolution stays fixed throughout a run. The score uses completed pixels per wall-clock second, including browser overhead. The WebGL2 driver path uses GPU fences. Software and WebGL1 paths complete 64 × 64 tiles using pixel readback and yield between batches so the page can handle Stop. A submitted tile can still delay input while the driver finishes it. Optional GPU timer queries add device-time diagnostics on the fence path; invalid timers are discarded. A readable-pixel check confirms output, but cannot detect every visual artifact.

Buffer throughput includes cache effects; it is not total RAM bandwidth. Graphics results describe these two WebGL scenes, not gaming FPS, VRAM capacity, or general compute performance. With SwiftShader, llvmpipe, or another software renderer, the CPU performs the graphics calculations. These are software graphics scores; combined stress loads the same CPU with both jobs.

How should I read stability data?

Variation is standard deviation ÷ mean throughput (lower is steadier). End / start compares the last third of samples to the first third, shown after at least six samples. A drop can come from heat, power limits, or background work; this page cannot identify the cause.

The fence path reports median and 95th-percentile completed frame latency, plus 1% low equivalent FPS. The tiled path reports completed tiles and full frames, with latency statistics from the first 10,000 measured tiles at most. A partial final frame contributes only its completed tile pixels to throughput. These timings include browser scheduling and readback; optional device timings are shown separately. Combined stress runs integer CPU work alongside the ray marcher and reports data without assigning a benchmark score.

Compatibility and fair comparisons

Designed for current Chromium browsers on Linux, macOS, and Windows. CPU needs Web Workers. Graphics accepts WebGL2 or WebGL1, including browser-provided software rendering such as llvmpipe or SwiftShader. WebGL1 falls back to medium shader precision when high precision is unavailable. If Chromium disables all WebGL contexts, this page cannot enable them; CPU-only mode remains available. This runs on Linux-capable boards such as the Arduino UNO Q when their browser exposes WebGL. The browser and driver choose the renderer; this page cannot install drivers or force hardware acceleration. Renderer names may be hidden for privacy, so software detection is best effort.

Use the same Chromium version and settings, plug in power, allow cooling between runs, and keep the tab visible. See BrowserBench’s comparison guidance. Results and history stay in this browser; Export downloads a local JSON file. Benchmark code makes no network submissions.
