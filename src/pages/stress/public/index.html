WHAT THE NUMBERS MEAN

Real measurements.
Transparent scoring.

This is a browser benchmark, influenced by Chromium, its JavaScript engine, graphics driver, power settings, and background apps. It does not certify hardware stability or replace a native diagnostic tool.

How do points work?

We use normalized throughput and geometric means, an approach used for workload groups in Geekbench 6. These are Stress Lab v1 points, with our own synthetic reference rates, not Geekbench, Cinebench, or 3DMark scores.

Each workload earns 1,000 × measured rate ÷ reference rate. CPU reference rates: integer 50 million iterations/s; floating point 10 million iterations/s; buffer 2,000 MB/s. GPU references: ray marching 25 MPix/s; texture sampling 250 MPix/s. These are fixed scale anchors, not a measured reference PC.

Each CPU score is the geometric mean of its three workload scores. GPU uses the geometric mean of its two scene scores. Overall is the geometric mean of CPU single, CPU multi, and GPU. Twice the throughput in every workload means twice the score. Overall requires a completed full suite.

What exactly runs?

CPU: deterministic integer hashing, dependent floating-point math, and a 1 MiB buffer read/write test per worker. Each block is checked against a known answer. Workers warm up for 150 ms before timing. Single worker is not a pinned physical core. Multi-worker tests use your selected count (up to 64); the default is capped at 16.

GPU: a 64-step torus ray marcher and 32 dependent texture samples per pixel, both at 1280 × 720, with 500 ms warmups. The score uses completed pixels per wall-clock second, including browser overhead. GPU fences prevent unbounded queued work and avoid display refresh limits. Optional GPU timer queries add device-time diagnostics; invalid timers are discarded. A readable-pixel check confirms output, but cannot detect every visual artifact.

Buffer throughput includes cache effects; it is not total RAM bandwidth. GPU results describe these two WebGL scenes, not gaming FPS, VRAM capacity, or general compute performance.

How should I read stability data?

Variation is standard deviation ÷ mean throughput (lower is steadier). End / start compares the last third of samples to the first third, shown after at least six samples. A drop can come from heat, power limits, or background work; this page cannot identify the cause.

GPU timing includes median and 95th-percentile completed frame latency, plus 1% low equivalent FPS. These include browser scheduling; optional device timings are shown separately. Combined stress runs integer CPU work alongside the ray marcher and reports data without assigning a benchmark score.

Compatibility and fair comparisons

Designed for current Chromium browsers on Linux, macOS, and Windows. CPU needs Web Workers. GPU needs hardware-accelerated WebGL2; if it is unavailable, CPU-only mode remains available. The driver chooses the GPU; a high-performance preference cannot force a specific adapter. Renderer names may be hidden for privacy.

Use the same Chromium version and settings, plug in power, allow cooling between runs, and keep the tab visible. See BrowserBench’s comparison guidance. Results and history stay in this browser; Export downloads a local JSON file. Benchmark code makes no network submissions.
